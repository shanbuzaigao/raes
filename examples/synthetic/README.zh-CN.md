# 虚构的离线示例

[English](README.md) | [简体中文](README.zh-CN.md)

**这里的所有内容都是虚构的。** 7 篇虚构的简短报告、8 条检索记录、保存的请求、AI 的回答以及一次人工裁决，全都是为本示例手工撰写的。这里没有任何真实的论文、被试、作者、DOI、API 回答或密钥。审计模型或裁决者的回答，是为这个角色事先写好的固定回答（fixture），不是任何模型的输出。

## 一条命令

在仓库根目录下，使用 Python 3.10 或更高版本运行：

```sh
python examples/synthetic/reproduce.py
```

该命令会核验 `FROZEN_INPUTS.json`，断开网络访问，根据保存的回答重建每一个判断和计算，再和 `expected/results.json` 比对：文本、编号、类别和整数必须完全匹配，浮点数允许 `1e-12` 的误差。随后，它会将结果写入仓库外部的一个临时新文件夹中，附带一份包含各文件哈希的清单，以及记录了 Python 版本和操作系统的 `runtime.json`。

使用 `--output <new folder>` 可以指定输出目录；该命令绝不会覆盖已有文件夹。不需要安装任何东西。

## 重点看什么

| 事件 | 它说明什么 |
|---|---|
| REC003 是 REC002 的重复项 | 一条检索记录不是一项研究 |
| SYN001 既有预印本又有期刊版本 | 同一批被试只算一次 |
| SYN005 是叙述性综述；SYN004 的研究对象是儿童 | 一篇在题目摘要阶段被排除，另一篇在全文阶段被排除 |
| SYN006 使用了“step cards” | 一条范围很窄的关键词规则把它误排除了；两个审计模型出现分歧，第三个支持纳入，一条附有引文行号的人工裁决确认了这次漏筛。随后规则得到修订（第 2 版补充了这个词），对所有候选论文重新运行全文筛选，修订后的规则把这篇论文纳入；没有任何记录靠手工加进纳入名单 |
| SYN001 报告 SD 10.0 和 SE 1.58 | 模拟的编码者误将 SE 填成了 SD；审计模型和盲审的裁决者各自独立得到 10.0 |
| SYN002 在重试成功前出现了一次格式错误的回答 | 失败的尝试不算排除，不算通过，也不算一条新的观测 |
| SYN003 缺少 SD | 该研究及对应的两条 arm 行照样编码；这组比较记为不可计算 |

数量：8 条检索记录，去重后 7 条，6 份全文，5 篇纳入报告，4 项研究，8 条 arm 行。可以计算的比较有 3 组，对应 6 条经过审计的行和 3 个效应量；1 组比较没有计算。14 个请求保存了 15 次尝试。1 条筛选排除被确认为漏筛，由修订后的规则纳入；1 处编码错误被确认并更正。

计算得出的效应量分别为 0.495177（SYN001）、0.443659（SYN002）和 0.393717（SYN006）；第二个效应量由 log odds ratio 换算而来，其余两个则通过合并标准差算得。这三个效应量没有合并：这个示例展示的是记录，不是结果。[NUMERICAL_METHODS.md](NUMERICAL_METHODS.md) 给出了具体的计算公式。

## 每个阶段在这里做什么

| 阶段 | 在这个示例里 |
|---|---|
| S0 | 填写完毕的小型纳入标准文件与 codebook；批准记录已明确注明为虚构 |
| S1 | 虚构的检索快照；不检索任何数据库 |
| S2 | 按精确匹配的键去重；不用文献管理软件 |
| S3 | 一条题目规则；这一阶段的审计只看题目和摘要 |
| S4 | 虚构的报告带有明确的头部字段，由一条范围很窄的关键词规则读取；这不是 PDF 解析器 |
| S5 | 因为集合很小，排除的记录全部审计；真实项目中会抽样并设有停止规则。确认的漏筛改了全文规则，第 2 版对全部候选重跑，剩下的那一条排除保留原来的审计结果。保存的审计回答采用了简化格式（纳入或排除、标准列表、一段引文），不是正式模板的格式 |
| S6 | 报告里印着自己的 Study-ID；不做相似度匹配 |
| S7 | 不需要：统计量都在正文里 |
| S8 | 每次请求处理一篇论文；检查列名与类型；每个数字都必须对应原文行号和引文 |
| S9 | 审计可计算的行；裁决者看到原始行和被质疑的字段，看不到提议的值；缺统计量的行不在这次审计之内 |
| S10 | 行编号来自只读的登记表；更正记在单独的日志里；两条计算路径 |
| S11 | 只做计数和算术核对；不做合并分析、元回归、偏倚诊断或功效分析 |
| S12 | 冻结输入、保存输出、生成输出哈希、在新文件夹中重建 |

回放程序是为这 7 篇虚构报告写的。它不是筛选真实论文的工具；真实项目用 `templates/` 里的筛选程序和自己的运行程序。

## 过程记在哪里

`inputs/requests.jsonl` 保存了每次请求及其哈希值；`inputs/responses.jsonl` 保存了每次尝试的原始文本（包含失败的尝试）。审计模型和裁决者收到同一份审计 codebook；裁决者能看到原始目标行和被质疑的字段，但看不到提议的更正值和它的理由。全文审计的请求里不包含筛选程序给出的判断和理由。

最终输出包括：原始编码行、核对更正后的行、更正记录、被裁决者驳回的质疑（本示例中为零）、可计算性记录、未解决项、报告与研究的对应关系表、两份审计日志、全文规则的各个版本以及每个版本各自纳入和排除了哪些记录、尝试日志、流程计数，以及 JSON 和 CSV 格式的效应量。引文和行号对得上，只说明这个值来自哪里，不说明它读对了；这正是 SE/SD 那个错误能通过证据检查、还需要审计的原因。

冻结覆盖来源文本、规则、请求和回答、预期输出以及计算代码；`inputs/` 和 `expected/` 里多出来的文件也会被拒绝。改动任何一个冻结文件，就意味着一个新版本和一份新清单。

回放成功，说明程序对已知输入做了该做的事。它不说明真实模型有多准确。
