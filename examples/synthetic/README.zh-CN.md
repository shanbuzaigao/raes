# 合成离线例子

[English](README.md) | [简体中文](README.zh-CN.md)

**全部材料均为编造。** 七份短报告、八条检索记录、保存的请求、AI 的回答和一条人工裁决，都是为这个例子手写的。没有真实的论文、被试、作者、DOI、API 回答或密钥。审计者和裁决者的回答是为该角色写的 fixture，不是任何模型的输出。

## 一条命令

在仓库根目录下，用 Python 3.10 或更新的版本运行：

```sh
python examples/synthetic/reproduce.py
```

这条命令先核验 `FROZEN_INPUTS.json`，切断网络，从保存的回答重建每一个判断和计算，再和 `expected/results.json` 比对：文字、编号、类别和整数必须完全一致，浮点数允许 `1e-12` 的误差。然后把结果写到仓库之外的一个新临时文件夹，附上结果的哈希清单和一份记录 Python 版本与操作系统的 `runtime.json`。

`--output <新文件夹>` 指定输出位置；已有文件夹不会被覆盖。不需要安装任何东西。

## 看什么

| 事件 | 它说明什么 |
|---|---|
| REC003 与 REC002 重复 | 检索记录不是研究 |
| SYN001 有 preprint 和 journal 两个版本 | 同一批被试只算一次 |
| SYN005 是叙述性综述；SYN004 研究儿童 | 一个在题目摘要阶段排除，一个在全文阶段排除 |
| SYN006 用的是 "step cards" | 窄的关键词规则把它错排了；两位审计者不一致，第三位支持纳入，一条带引文行号的人工裁决确认这是漏筛。随后修订规则（第 2 版加上这个词），全文筛选对全部候选重跑，修订后的规则把它纳入；没有任何记录靠手工加进纳入名单 |
| SYN001 报告了 SD 10.0 和 SE 1.58 | 模拟的编码者把 SE 填成了 SD；审计者和看不到建议的裁决者各自独立得到 10.0 |
| SYN002 第一次回答格式不完整，重试后有效 | 失败的尝试不是排除、不是通过，也不是新的观测 |
| SYN003 没有 SD | 研究和两条 arm 行照样编码；这组比较记为不可计算 |

数量：8 条检索记录，去重后 7 条，6 份全文，5 份纳入报告，4 项研究，8 条 arm 行。3 组比较可计算，对应 6 条审计行和 3 个效应量；1 组比较保持不可计算。14 个请求有 15 次保存的尝试。1 条筛选排除被确认为漏筛、由修订后的规则纳入，1 项编码错误被确认并改正。

效应量是 0.495177（SYN001）、0.443659（SYN002）和 0.393717（SYN006）；第二个由 log odds ratio 换算，另外两个用合并标准差。这里不合并它们：例子展示的是记录，不是结果。公式见 [NUMERICAL_METHODS.md](NUMERICAL_METHODS.md)。

## 每个阶段在这里做什么

| 阶段 | 在这个例子里 |
|---|---|
| S0 | 填好的小纳入标准文件和 codebook；批准记录为虚构，并明确注明这一点 |
| S1 | 编造的检索快照；不检索任何数据库 |
| S2 | 按精确键去重；不用文献管理软件 |
| S3 | 一条题目规则；这一阶段的审计只看题目和摘要 |
| S4 | 编造的报告带有明确的字段，由一条窄的关键词规则读取；这不是 PDF 解析器 |
| S5 | 排除的记录全部审计，因为集合极小；真实项目抽样并有停止规则。确认的漏筛改了全文规则，第 2 版对全部候选重跑，剩下的排除保留原来的审计结果。保存的审计回答用的是简化格式（纳入或排除、一组标准编号、一句引文），不是正式模板的格式 |
| S6 | 报告里印着 Study-ID；没有相似度匹配 |
| S7 | 不需要：统计量都在文字里 |
| S8 | 每篇论文一个请求；核对列名和类型；每个数字都要有行号和引文 |
| S9 | 审计可计算的行；裁决者看到原始行和被质疑的字段，看不到建议值；缺统计量的行不在这次审计之内 |
| S10 | 行编号来自只读的登记簿；改正记在单独的日志；两条计算路径 |
| S11 | 只做数量和算术核对；不合并，不做元回归、偏倚诊断或功效分析 |
| S12 | 冻结输入，保存输出，输出哈希，在新文件夹里重建 |

回放程序是为这七份编造的报告写的，不是筛真实论文的工具；真实项目用 `templates/` 里的筛选程序和自己的运行程序。

## 过程记在哪里

`inputs/requests.jsonl` 保存每个请求及其哈希；`inputs/responses.jsonl` 保存每次尝试的原始文本，包括失败的。审计者和裁决者拿到同一份审计 codebook；裁决者拿到原始目标行和被质疑的字段，拿不到建议的改正值和理由。全文审计的请求里没有筛选程序的判断和理由。

输出包括原始编码行、核对更正后的行、改正记录、被裁决者驳回的质疑（这个例子里没有）、可计算性记录、待定项、报告与研究的对应表、两份审计日志、全文规则的各个版本及各自纳入和排除的记录、尝试日志、流程计数，以及 JSON 和 CSV 两种格式的效应量。引文和行号对得上，只说明这个值来自哪里，不说明读对了；这正是 SE/SD 那个错误能通过证据核对、需要审计的原因。

冻结覆盖来源文本、规则、请求和回答、期望输出和计算代码，`inputs/` 和 `expected/` 里多出文件也会被拒绝。改冻结文件意味着新版本和新清单。

回放成功说明程序对已知输入的行为正确。它不说明真实模型有多准。
